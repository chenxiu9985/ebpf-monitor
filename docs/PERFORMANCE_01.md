# VMware 性能拆分、批处理优化与回归

日期：2026-09-26（实验从 09-25 开始）。目标 VM：Ubuntu / Linux 6.8.0-136-generic、2 vCPU、约 3.78 GiB、ext4。构建工具：clang 18.1.3、libbpf 1.3.0、bpftool 7.4.0。完整环境版本见实验归档 `environment.txt`。

## 1. 保留的改动

1. 增加分阶段基准：B0 无监控、P0 仅内核构造/配对、P1 传输后不编码、P2 编码后丢弃、B1 正常 JSONL。诊断模式显式标记，禁止与 socket 分析或阻断混用。
2. 增加批量读取：默认 10 ms 周期主动读取 ring buffer，内核使用 NO_WAKEUP 减少频繁唤醒；`--batch-ms 0` 可恢复原自适应通知，支持 0–50 ms。事件字段、时间戳和检测规则不变，未通过采样或删事件来降低开销。
3. 增加同二进制的批处理对照、源码/二进制摘要、环境标签、逐轮数据、采集器 CPU、排空与退出耗时，以及诊断模式接收计数/输出约束检查。历史原始 JSON 保留，新结果移除硬编码“不是 VMware”的错误说明。
4. 增加三项 CLI 回归（包含多个子场景），验证诊断与分析/阻断互斥、非法批处理间隔在加载前被拒绝。

修改文件：`bpf/monitor.bpf.c`、`collector/main.c`、`scripts/benchmark.py`、`tests/test_collector_cli.py`；运行说明与实验矩阵同步更新。

## 2. 如何定位问题

每组五轮，每轮 20,000 次打开、1,000 次短进程执行，各组轮换顺序。以下是关闭批处理时的五阶段实测；B1 包含采集器与 JSONL，没有 Python 分析器。

| 分组 | 中位负载耗时 | 相对 B0 吞吐下降 |
|---|---:|---:|
| B0 无监控 | 4.2444 s | — |
| P0 内核构造/配对/计数，跳过 ring 输出 | 4.9442 s | 14.15% |
| P1 正常内核输出、接收后不编码 | 6.5515 s | 35.21% |
| P2 编码后丢弃 | 6.5123 s | 34.82% |
| B1 正常 JSONL | 6.3165 s | 32.80% |

结果支持优先检查事件传输和唤醒成本；各组会受调度与虚拟化波动影响，不能按差值精确拆出可相加的成本。P0 仍包含探针、字段读取、map 配对和计数，也不能当作空探针成本。诊断模式主动省略事件输出，零丢失计数不意味着保存了完整监控数据。

先前尝试过宿主机 PID 过滤快路径，但正常模式吞吐下降从 31.07% 变为 32.05%，未显示收益，已撤回。候选源码 `candidate-monitor.bpf.c` 与前后原始结果保留。这些不同时间的基线不能代替下表同二进制对照。

## 3. 批处理的同条件对照

使用最终同一个采集器二进制，轮换 B0、`--batch-ms 0`、`--batch-ms 10`，五轮、同样的 20,000/1,000 负载。所有被测轮次的 ring/map/queue/unpaired 计数均为 0。

| 指标 | 原通知模式（0 ms） | 批处理（10 ms） |
|---|---:|---:|
| 负载中位耗时（B0 为 4.2608 s） | 6.3203 s | 5.0266 s |
| 负载期间吞吐下降 | 32.56% | **15.24%** |
| 含排空及退出的中位耗时 | 7.0968 s | 5.8048 s |
| 含排空及退出的吞吐下降 | 39.96% | **26.60%** |
| 负载期间采集器 CPU 时间中位数 | 1.42 s | 0.38 s |

此前一组独立五轮对照也观察到相同方向：原模式 33.50%、10 ms 模式 16.18%。这些是当前受控 VM 微基准结果，不代表任意业务或所有内核上的收益。

`seconds` 沿用原实验的负载耗时口径；`completion_seconds` 额外包含排空、detach 和进程退出，两种模式的附加时间中位数均约 0.779 s。因此计入退出成本后收益仍存在，但这部分是有限运行生命周期成本，不能当作持续服务的稳态开销。采集器 CPU 只统计负载期间自身 CPU，内核探针还会消耗被监控进程的 CPU；没有据此宣称整机 CPU 降幅。

**低于 5% 的目标仍未达到。** 本轮完成了可验证的改善，不关闭 T30；尚未运行完整 B2/B3 分析器性能、真实应用负载和一小时稳定性实验。

| 10 ms 模式的五阶段自检 | 一轮 1,000/100 的模式验证通过；验证诊断计数和普通事件不输出，不用于性能排名 |

过载恢复通过不等于过载时零丢失。正常基准、集成和边界的零计数仅针对本次固定负载；10 ms 批处理在更高事件率或调度延迟下仍可能增加等待与 ring 压力。保留 `--batch-ms 0` 便于回退对照。
