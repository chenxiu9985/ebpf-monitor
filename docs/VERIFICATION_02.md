# 第二轮修复与验证报告

日期：2026-09-24。环境仍为 WSL Ubuntu 24.04 / Linux 6.6.87.2，目标 VMware 尚未连接。本报告记录新增证据，不覆盖第一轮失败结果。

## 已修复的问题

1. **卸载阶段配对统计污染。** 增加卸载前指标后，实测 unpaired 从卸载前 0 变成卸载后 11。原采集器逐个移除入口与出口挂点，拆卸期间其他进程的调用可能只有出口。新增统一采集开关：全部挂点和 ring buffer 读取器就绪后开启，拆卸前关闭。未完整落在观察窗口内的调用不保证采集；活动窗口内配对失败仍计数，不通过清零计数掩盖问题。
2. **祖先映像被后续 exec 改写。** 子进程首次观测时保存有界祖先来源快照，告警引用当时的 exe、代次和 exec 证据。父进程随后 exec、退出或被缓存淘汰不会改写该来源。首次观测时缺少的祖先仍明确为未知，不能补造启动前历史。
3. **重复过滤检查。** 自身/分析器排除提前到事件初始化之前，移除输出阶段的重复 namespace 检查；入口与出口仍分别检查。边界和完整链路回归通过，但本次性能实验没有证明这项优化带来显著收益。

## 功能与延迟

| 实验 | 结果 | 数据目录 |
|---|---|---|
| 自动化回归 | 40 项通过，包括父进程 exec、淘汰后来源保留 | out/unit-tests.log |
| 真实内核边界 | 12 项通过；unpaired、ring/map/queue 丢失均 0 | out/edges-filter-01 |
| Linux 本地磁盘集成第一组 | UID1000、30 轮通过；P95 245.55 ms | out/integration-ext4-01 |
| 历史来源修复后集成 | UID1000、30 轮通过；P95 245.97 ms | out/integration-history-01 |

三次本地磁盘运行均未对两类合法例外产生告警。最终运行 events_attempted=2004，ring_lost=map_fail=queue_lost=unpaired=0。固定受控用例的零误报不能解释为真实主机误报率为零。

这里“本地磁盘”指测试输出最初写入 Linux `/tmp`，实验结束才复制回项目目录；源码和构建产物仍在 Windows 挂载目录。此前共享目录输出的 P95 为 713–736 ms。本次结果说明存储位置对该链路有明显影响，但并非严格随机化的单变量对照，不能把全部差值归因于某一个机制。

## 性能未达标

五轮交替 B0/B1 实验，每轮 20,000 次文件打开、1,000 次短进程执行，输出写入 Linux 本地磁盘。B0 不监控，B1 为采集器及 JSONL 输出；没有分析器。吞吐下降定义为 `1 - B0中位耗时 / B1中位耗时`。

| 版本 | B0 中位耗时 | B1 中位耗时 | 吞吐下降 |
|---|---:|---:|---:|
| 采集边界修复后 | 0.8003 s | 1.0407 s | 23.10% |
| 去除重复过滤后 | 0.7533 s | 0.9827 s | 23.35% |

两次基线也发生变化，不能宣称优化产生了可测的吞吐收益。负载比原来的 2,000/100 增大十倍，与此前短样本 9.2%/13.86% 不能直接当作回归对照。该微基准对系统调用探针开销很敏感，不是通用业务开销；仍不满足计划低于 5% 的目标。下一步需要拆分探针、编码、持久化成本并增加真实应用负载。

## 检测消融

对 `out/integration-history-01` 同一份真实采集日志，使用原实验规则分别启用：

| 分组 | 工作进程告警 | 合法例外告警 |
|---|---|---:|
| 单事件规则 | R01、R02、R03 各 30 条 | 0 |
| 加入进程来源 | 额外 R04 30 条 | 0 |
| 加入序列关联 | 额外 C01、C02 各 30 条；分别关联 3、2 条事件证据 | 0 |

这验证了上下文和序列带来的额外解释信息，不证明独立攻击类别上的检出提升。关闭告警规则并未移除引擎计算，因此也不是 CPU/性能消融。结果和三组 HTML 报告位于 `out/ablation-01`。
